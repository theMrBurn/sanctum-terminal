The project is in better shape than it feels. **~45 systems are DONE
on main.** The frustration is concentrated in three places:

1. **One uncommitted feature branch holding 13 EXPERIMENTAL systems hostage.**
   `feat/make-brain-ping-pong` carries make-brain substrate + ping_pong V1 +

   merge. Per memory `project_make_brain_ping_pong_v1`: "awaiting UAT before
   main merge."

   live consumer. ~12 systems in this state. Each represents a binary

   in progress" — they are **decision debt**.

3. **Three memory pins are stale** and giving wrong advice; one
   `LIVE_PIPELINE_MAP.md` entry is wrong. Each gets a one-line fix.

**Critical path to clean state:**
- Run UAT on the active branch → unblocks 13 systems → cluster collapses
- Make 3 retire-or-wire decisions on orphan clusters → ~12 systems graduate
- Refresh stale memory pins (Claude can do this in one pass)

Everything else is content/polish work, not architectural.

- **`project_vector_workroom_v1.md`** says "V1 SHIPPED 2026-05-02. PRs 1-5 done. 119/119 tests." But `.claude/feature/feat_vector-workroom.md` still has PR 6 marked 🟡 UAT in progress. Memory and feature doc disagree on whether V1 is closed.

### LIVE_PIPELINE_MAP.md correction needed

- **`ambient_life.py` is mislabeled "live"** at `LIVE_PIPELINE_MAP.md:33`. The file imports `panda3d.core` at module top (`core/systems/ambient_life.py:22`). `brain_server.py` does NOT import it (verified by grep). All importers are Panda3D legacy (`cavern.py`, `tools/extract_meshes.py`, `tools/export_glb.py`). Per the hard rule, this is LEGACY. The map needs a correction.

### Pre-existing test bugs (not from PR 9/10)

- **`tests/test_volley_telemetry.py:36-44`** `_send_ball_out` puts ball at `pos=(0.0, -2.0, 1.6)`, but vanilla profile `out_of_bounds_y=-3.0` (`ping_pong.py:88`). `-2.0 < -3.0 → False` so the rally never resolves. `test_match_win_closes_run_as_won` and likely a few siblings hang in serial runs. Tuning happened in commit `7055e77`; tests not updated.
- **`tests/test_volley_chamber_boot.py:101`** asserts chamber size `[12.0,12.0,12.0]` but `CHAMBER_GEOMETRY['size']` is now `[12.0,36.0,8.0]` (UAT-derived per same commit). 8 of 30 chamber_boot tests fail outright.

### Naming collisions worth noting

- **`design_ghost_seeds_registry`** (content registry: boulder/stalagmite/column shapes) is NOT the same as **`ghost_profile_engine.py`** (avatar behavioral fingerprint). Pin name suggests they're connected; code says otherwise.
- **`design_shadow_proxy`** describes the proven `decal_projector` sandbox in Godot's `feat/render-manifest`. The Python file `glow_decal.py` is unrelated Panda3D-era code despite the name overlap.

### LIVE_PIPELINE_MAP gap

- **`encounter_session.py` is in the live list but its transitive deps** (`encounter_engine.py`, `encounter_resolver.py`, `actor.py`, `encounter_config.py`) are not. Map is technically truthful (only session is brain-imported directly) but the reader gets a misleadingly narrow view of live encounter machinery.
